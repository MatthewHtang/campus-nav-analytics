MILESTONE 1 DESIGN

1. Custom hash table (Matthew)
Facility IDs are trimmed and converted to uppercase before use. Valid IDs
are F followed by three digits. Starting at h = 0, each character c updates:
    h = (h * 31 + c) % capacity
The default capacity is INITIAL_CAPACITY = 11. No library hash is used.

2. Collision strategy and counting
Separate chaining uses vector<vector<Entry>>: the outer vector holds buckets,
and each inner vector holds that bucket's entries. These are vectors, not
linked lists. Chaining is simple and allows more facilities than buckets.
Each accepted insertion into a nonempty bucket counts as ONE collision.
Rejected duplicates do not change entries or collisions and keep the first
record. Lookup hashes the ID and searches only its bucket.
F001 and F013 collide at capacity 11. testdata/collision includes both and
a lowercase duplicate f001: expected entries 2, rejected 1, collisions 1.

3. Capacity
Capacity limits buckets, not records. Chains grow dynamically; there is no
fixed full-table rejection. Construction clamps a nonpositive capacity to 1
and allocates that many buckets. The table does not rehash or resize later.

-------------------------------------------------------------------------------------------

4. Graph (Alka, with shared loading work)
CampusGraph stores building names and a vector of neighbor lists. An adjacency
list is suitable because each building connects to relatively few others;
it stores O(V + E) information. Buildings and neighbors keep insertion order.
Each walkway is saved at both endpoints but counted once. Duplicate/reversed
edges, self-connections, and unknown endpoints are rejected. All graph
features use this same representation. BFS uses a queue and marks a building
visited when enqueued. The start has distance 0 and counts as reachable.

-------------------------------------------------------------------------------------------

5. Department tree (Sankalp)
DepartmentNode stores a name, parent pointer, depth, and vector of child
pointers. Any number of children is allowed. DepartmentTree owns and deletes
all nodes; copying is disabled to prevent duplicate deletion. The first valid
record requires parent NONE. Other parents must already exist. Names match
ignoring case and outer whitespace. Hierarchy and preorder visit children in
insertion order; hierarchy indents four spaces per depth. Menu additions
change memory only. An empty tree accepts a root without a parent prompt.

6. Main modules
Facility: stores ID, name, canonical building spelling, and category.
HashTable: stores normalized IDs and indexes into the facilities vector.
FacilityDatabase: loads, validates, displays, and searches facilities; keeps
first accepted category spelling and facility file order.
CampusGraph: buildings, walkways, graph display, degrees, and BFS.
DepartmentNode/DepartmentTree: department records, loading, add/search,
hierarchy, and preorder.
Utils: trimming, splitting, case conversion, ID validation, record reading,
warnings, summaries, and whole-line menu input.
main.cpp: coordinates ordered loading and menu choices 0 through 9.

7. Scope
Postorder, level-order, statistics, shortest paths, and reports are Final
features. Their existing code is not required to finish Milestone 1.
